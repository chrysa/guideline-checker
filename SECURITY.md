## Security posture of the product itself (FACT)

- **Auth is pluggable** (`web/auth.py`, `web/mode.py`): `AUTH_MODE = disabled | api_key (default) |
  local | ldap | oidc`, credentials env-driven (`.env.example`). `.env.example` explicitly warns
  "NEVER disable in production".
- **Security headers**: `web/security_headers.py`.
- **Deterministic/offline core**: the LLM proposer is opt-in (`GC_CLAUDE` / `GC_OLLAMA`) and can
  never write autonomously — proposals are replayed in a sandbox and require validation before
  persist (D-0011/D-0012, `workshop/*`). Reduces the blast radius of the AI seam.
- **`fleet` uses the `gh` CLI** (`fleet/gh_client.py`) — relies on the operator's authenticated
  `gh` session; no embedded tokens (FACT).
- **CI security gates**: `.github/workflows/secret-scan.yml`, `pre-commit.yml`, `pip-audit` in the
  `dev` extra, `.gitleaks.toml`.

   misconfiguration would expose `/api/*` scan-trigger endpoints unauthenticated. Confirm the web

   `guidelines/*.yml`. Ensure the deployed `SCAN_ROOT` and write scope are constrained to intended
